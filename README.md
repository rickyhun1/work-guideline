# 업무표준 관리

회사의 업무표준(매뉴얼·프로세스·지침)과 양식, 관련 법령, 업무 프로젝트를 한곳에서 조회·관리하는 프로그램입니다.
ISO 9001·14001·45001 통합 경영시스템 문서 45개(타사 양식에서 추출)를 기본 데이터로 넣어 두고 시작합니다.

- PC 관리 프로그램: Windows 전용 (웹 브라우저를 쓰지 않음, 호스팅 비용 없음)
- 지금은 PC 한 대에서 혼자 쓰고, 나중에 회사 서버 컴퓨터에 서버를 두고 여러 명이 권한별로 쓰는 구조
- 사규 관리 프로그램(regulation-manager)과 같은 기술로 만들었지만 완전히 별도 프로그램

---

## 1. 설치·실행 (Windows)

1. GitHub Actions 또는 Releases에서 `WorkGuideline-x.x.x.zip`을 내려받습니다.
2. 압축을 끝까지 풀고 `WorkGuideline.exe`를 실행합니다.
   - **"Windows의 PC 보호"** 창이 뜨면 **추가 정보 → 실행**. (서명 없는 프로그램이라 처음 한 번)
3. 처음 실행하면 데이터베이스를 준비하고 기본 문서를 넣습니다 (수십 초).
4. 관리자 계정을 만듭니다. 이 계정은 **총무팀** 소속 관리자가 됩니다.

| 항목 | 내용 |
|---|---|
| 데이터 위치 | `C:\ProgramData\WorkGuideline` (DB, 양식·첨부 파일) |
| 백업 | 프로그램을 닫고 위 폴더를 통째로 복사 |
| 업데이트 | 프로그램을 닫고 새 zip을 풀어서 실행. 데이터는 그대로 |
| 포트 | 37220 (사규 관리 프로그램과 동시에 켜도 충돌 없음) |

## 2. 기능

| 메뉴 | 내용 |
|---|---|
| **첫 화면** | 문서·양식·법령·프로젝트 건수, 기한이 다가오거나 지난 항목, 최근 변경 |
| **업무표준** | 매뉴얼·프로세스·지침. 목적·범위, 프로세스 자원, 주요업무절차, 단계별 입력·업무·출력·**전결권한**, 결재라인, 요구사항(ISO 조항·법·규제), 성과지표, 관련 프로세스(서로 이동), 개정이력, 첨부 |
| **양식** | 양식번호·보존년한·결재란, 엑셀 파일 보관. 새 버전을 올리면 이전 버전도 남음. 내려받을 때 **현재 번호로 파일 이름**이 붙음 |
| **법령** | 직접 입력 (법령명·조항·조문 내용·시행일·링크·메모). 조문 내용까지 검색, 문서와 연결 |
| **프로젝트** | 지원사업 신청·인증심사 등 건별로 참여부서, 필요서류(항목), 담당, 기한, 상태, 연결 양식, 제출서류 첨부. 기한 색 표시(지남/7일 이내), 복제, 체크리스트 엑셀 |
| **변경이력** | 누가·언제·무엇을 (변경 전 → 후). 모든 등록·수정·삭제·업로드·번호변경·내보내기 |
| **통합 검색** | 문서 내용, 양식, 법령 조문, 프로젝트를 한 번에 |
| **설정** | 번호 체계, 부서, 사용자, 권한, 회사 정보(내보내기 머리글, 결재 직책) |

### 번호 체계
- 문서 구분(매뉴얼/프로세스/지침…)과 접두어, 번호 형식을 바꿀 수 있습니다.
  - 문서번호 형식 예: `{prefix}-{num}` → `P-801`, `KS-{prefix}-{num}` → `KS-P-801`, `{prefix}{num:04}` → `P0801`
  - 양식번호 형식 예: `{doc}-{seq:02}` → `P-801-01`, `{doc}-F{seq:02}` → `P-801-F01`
- **미리보기**로 바뀔 번호를 확인한 뒤 **일괄 적용**. 문서·양식마다 번호를 직접 지정하면 일괄 적용에서 빠집니다.
- 문서·양식은 내부 id로 연결되어 있어 번호가 바뀌어도 관계가 끊기지 않습니다.

### 내보내기
- **개별**: 문서 → 원본과 비슷한 배치의 엑셀(머리글, 개정이력, 작성·검토·승인란, 목적·범위, 프로세스 분석, 요구사항, 관련 양식, 업무절차 표). 양식 → 최신 파일. 법령·프로젝트 → 엑셀.
- **묶음(zip)**: 목록에서 체크한 문서·양식·법령·프로젝트를 한 번에. 인증 제출용으로 바로 쓸 수 있게 정리됩니다.
  ```
  00_문서목록표.xlsx
  업무표준/프로세스/P-1001 부적합 및 시정조치/P-1001 부적합 및 시정조치.xlsx
  업무표준/프로세스/P-1001 부적합 및 시정조치/양식/P-1001-01 부적합 및 시정조치 요구서.xlsx
  양식/… 법령/법령 목록.xlsx  프로젝트/<이름>/체크리스트.xlsx, 제출서류/…
  ```

### 권한
- 메뉴별(업무표준·법령·프로젝트·변경이력) 4단계: 없음 / 조회 / 등록·수정 / 등록·수정·삭제
- 실제 권한 = max(모든 사람 기본값, 부서 권한, 개인 권한). 관리자는 전부.
- **처음 설정: 총무팀만 등록·수정·삭제, 나머지는 조회.** 나중에 [설정 → 권한]에서 부서·개인별로 늘리면 바로 반영됩니다.
- 권한은 서버에서 매 요청마다 확인합니다 (프로그램을 조작해도 우회 불가).

### 여러 사람이 같이 쓸 때
- 두 사람이 같은 문서를 동시에 고치면 나중에 저장한 사람에게 "다른 사용자가 먼저 수정했습니다"가 뜹니다 (덮어쓰지 않음).

## 3. 회사 서버로 옮기기 (나중에)

1. 서버 컴퓨터에 이 프로그램을 풀고, `server` 폴더에서 서버를 상시 실행합니다 (`HOST=0.0.0.0`).
   또는 PostgreSQL을 따로 두고 `server/src/server.js` 를 `DATABASE_URL`, `JWT_SECRET`, `DATA_DIR`, `PORT` 와 함께 실행.
2. 각 PC의 프로그램: [설정 → 연결 설정 → 서버에 접속]에 `http://서버주소:포트` 입력.
3. 기존 PC 데이터는 `C:\ProgramData\WorkGuideline` 을 옮기면 됩니다.

조회 전용 모바일 앱은 같은 서버 API를 쓰도록 나중에 `mobile/` 에 추가할 예정입니다.

## 5. 개발 메모

| 폴더 | 내용 |
|---|---|
| `server/` | Node.js 22 + Fastify 5 + PostgreSQL. `src/routes/*` API, `migrations/*.sql` (시작 시 자동 적용), `src/local.js` PC 단독 실행(내장 PostgreSQL), `seed/` 기본 데이터 |
| `server/src/lib/xlsx.js` | 문서·목록·법령·프로젝트 엑셀 생성 (exceljs) |
| `app/` | Flutter (Windows). `lib/screens` 화면, `lib/widgets` 공통 부품 |
| `.github/workflows/check.yml` | 서버 시험 + Flutter 검사·시험 (로그: `ci-logs-server`, `ci-logs-analyze` 브랜치) |
| `.github/workflows/build-windows.yml` | Windows 빌드 → 서버 시작·종료 시험 → zip. main 이면 Releases 에 올림 (로그: `ci-logs-windows`) |

```bash
# 서버 시험 (PostgreSQL 필요, DB 이름에 test 포함)
cd server && npm ci
DATABASE_URL="postgres://USER@localhost/work_guideline_test" npm test
```
